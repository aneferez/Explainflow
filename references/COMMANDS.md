# ExplainFlow Command Reference

## Visual & structured explanation commands

- `/visualnotes` — visual study notes with boxes, arrows, icons, and concise callouts
- `/stickynotes` — sticky-note style grouped explanation
- `/mindmap` — hierarchical mind map
- `/infographic` — infographic-style structured explanation
- `/flowchart` — process or decision flow
- `/diagram` — labeled conceptual or system diagram
- `/architecture` — software/system architecture
- `/timeline` — chronological sequence
- `/roadmap` — learning or development roadmap
- `/cheatsheet` — compact one-page-style reference
- `/conceptmap` — relationships among concepts
- `/tree` — tree hierarchy
- `/pipeline` — input → processing → output
- `/workflow` — end-to-end workflow
- `/funnel` — funnel stages
- `/layers` — layer-by-layer explanation
- `/flashcards` — revision flashcards
- `/comparison` — side-by-side comparison
- `/quiz` — knowledge-check questions
- `/eli10` — explain for a roughly 10-year-old audience
- `/beginner` — beginner-friendly explanation
- `/expert` — advanced technical explanation
- `/teacher` — teach step by step
- `/mentor` — guide the user through reasoning and next actions
- `/stepbystep` — numbered sequential breakdown
- `/keypoints` — only the highest-value points
- `/summary` — concise structured summary
- `/examples` — explanation driven by examples
- `/crashcourse` — accelerated practical overview
- `/deepdive` — detailed technical exploration

## Routing notes

If multiple commands are supplied, combine them in the order given when compatible.
Example: `/summary /flowchart` → concise summary first, then a flowchart.

If two commands conflict, prioritize the first command and use the second only where useful.
